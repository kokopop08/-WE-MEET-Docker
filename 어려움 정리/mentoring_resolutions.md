# 🎓 교수님 멘토링 대비 최종 보고 및 질문 정리

본 문서는 교수님의 기존 조언을 바탕으로 우리 팀이 실제로 겪은 한계와 해결한 결과들을 쉬운 용어로 정리하고, 멘토링 당일 교수님께 추가적인 조언을 구하고자 하는 **[문제 >> 요청]** 구조의 질문지 최종본입니다.

## 1. 🌟 우리가 해결하고 완성한 사항 (쉽게 정리한 성과)

* **[문제 1] 분산 연산 결과가 격리되어 합쳐지지 않던 현상**
  * **쉽게 설명:** 여러 대의 가상 컴퓨터(컨테이너)가 각자 따로 학습한 결과(가중치 조각)를 저장해도, 서로 격리된 방에 갇혀 있어서 병합 워커가 접근하지 못해 모델 합치기(FedAvg)가 실패했습니다.
  * **해결 내용:** 공동 분산 폴더(도커 공유 볼륨)를 구축하여, 워커들이 마스터(헤드) 노드를 거치지 않고 중간 결과물을 직접 읽고 쓰는 구조를 실현했습니다. **(교수님의 Ray P2P 데이터 교환 피드백 완벽 반영)**
* **[문제 2] 가상 노드가 꺼졌을 때 연산이 멈춰버리는 고가용성 부재**
  * **쉽게 설명:** 스팟 노드가 갑자기 회수(Eviction)되거나 연결이 끊어지면, 쪼개서 학습 중이던 조각 태스크가 미완성으로 유실되어 전체 연합 학습이 무한 대기 상태에 빠졌습니다.
  * **해결 내용:** 전역 상태판에 작업의 족보(Lineage DAG)를 실시간으로 써둡니다. 특정 노드가 죽는 즉시 족보를 역추적하여 유실된 중간 작업만 대기 큐의 0순위로 긴급 환원시켜 다른 노드가 이어서 훈련하도록 **장애 자가 복구(Cascaded Recovery)**를 구현했습니다.
* **[문제 3] 훈련 반복 시 남겨지는 중간 가중치 조각 파일의 용량 누수**
  * **쉽게 설명:** 연산이 반복될 때마다 생성되는 수많은 임시 가중치(`.pt`) 파일들이 하드디스크에 쌓여 윈도우/WSL2 가상머신 영역의 저장 공간과 램 자원을 서서히 잠식했습니다.
  * **해결 내용:** 합산(Reduce)이 완수되어 최종 통합 모델 가중치 파일이 저장되는 즉시, 재료로 쓰인 조각 파일들을 시스템에서 자동 청소(`os.remove`)하여 용량 누수를 0%로 만들었습니다.

## 2. 🔀 교수님 피드백 반영 사항 (이종 ML 모델 자율 융합 배치)

* **[문제] 모델 종류마다 컴퓨터 자원을 쓰는 패턴이 달라 생기는 연산 지연**
  * **쉽게 설명:** 연산만 엄청나게 하는 모델(CNN)과 데이터 전송/메모리 통신을 아주 빡빡하게 타는 모델(RNN/LSTM)이 섞여 있을 때, 같은 종류만 한 노드에 무작위로 묶어 배정하면 자원 병목 현상(Straggler)이 발생합니다.
* **[해결 방향] 강화학습 보상 조절(Reward Shaping)을 통한 자율 융합 배치 (Co-scheduling):**
  * 개발자가 직접 코딩한 고정 규칙(Heuristics) 대신, 강화학습 에이전트의 보상 수식에 **"이종 모형 융합 보상점수"**를 반영했습니다.
  * 이미 메모리를 가득 물고 있는 RNN 노드에 연산 위주의 CNN을 교차 융합 할당하면 **에이전트에게 추가 보상(+0.15)**을 주고, 병목을 가중시키는 동종 배정을 고집하면 **패널티(-0.20)**를 주어 학습시킵니다.
  * 이를 통해 강화학습 에이전트 스스로 클러스터 자원 구조를 파악하고, 최적의 교차 융합 배치를 유도해 내는 인공지능 스케줄러를 완성했습니다.

## 3. ❓ 교수님께 추가 피드백을 구하고 조언을 얻고자 하는 내용

### 📌 질문 1. Spot 인스턴스 강제 회수 환경 하에서의 안정적 가중치 병합(.pt) 및 단일 장애점(SPOF) 제거
* **[어려움 / 문제]**
  * 각 가상 워커들이 훈련한 로컬 가중치(`.pt`) 파일들을 한데 묶는 연산(FedAvg)은 매우 무겁습니다. 현재 아키텍처에서는 작업 중 스팟 노드가 갑자기 탈락(Eviction)되는 상황을 극복하기 위해, 병합 작업을 무조건 안정적인 온디맨드 단일 노드(`worker-1`)에만 전용 고정하여 처리하고 있습니다.
  * 하지만 이로 인해 해당 온디맨드 노드가 과부하되거나 죽을 경우 전체 분산 시스템이 통째로 멈추는 **단일 장애점(SPOF)** 한계가 있습니다.
* **>> [피드백 요청 사항]**
  * 불안정한 스팟 노드들의 탈락 가능성을 전제하면서도, 특정 안전 노드에 의존하지 않고 **스팟 노드들 간에 분산 합의 알고리즘(예: 탈중앙화된 Ring-AllReduce 방식이나 분산 가중치 합의 모델)을 설계하여 안정적이고 유연하게 .pt 결합 모델을 완성해 내는 해법**에 대해 조언을 구합니다.

### 📌 질문 2. 서비스 안정성(SLA 보장)과 강화학습 탐험(Exploration)의 밸런스 조정
* **[어려움 / 문제]**
  * 스케줄러가 Q-Learning 강화학습을 수행할 때 최적의 길을 찾아내려면 일부러 엉뚱한 결정을 내려보는 탐험(Exploration)이 필수적입니다. 그러나 이 과정에서 부적절한 노드 배정이 발생하여 일시적으로 마감 시한(SLA)을 초과하는 미완 상태가 발생합니다.
* **>> [피드백 요청 사항]**
  * 실 서비스의 안정성(SLA 준수율)을 해치지 않으면서도 에이전트가 학습 성과를 낼 수 있도록, 남은 마감 기한 위험도에 따라 탐험 확률을 강제 제어하는 **'안전 제한적 강화학습(Safe RL)'** 제약 조건 설계를 분산 스케줄러에 추가하는 방향이 학술적으로 타당한 접근인지 여쭤보고 싶습니다.

### 📌 질문 3. 자원 인지형 동적 스케일링의 가상화 오버헤드 딜레마
* **[어려움 / 문제]**
  * 호스트 램이 부족할 때 스팟 노드를 동적으로 띄우는 오토스케일러를 구현했으나, 가상머신(WSL2) 및 도커 엔진 자체의 구동 비용과 파일 캐싱 점유율 (`Vmmem` 비대화) 때문에 오히려 윈도우 전체 시스템의 백그라운드 오버헤드가 크게 상승하는 딜레마를 겪고 있습니다.
* **>> [피드백 요청 사항]**
  * 자원 한계를 극복하기 위해 물리적 가상 컨테이너를 동적으로 늘리는 오버헤드 비용과, 단일 컨테이너 내부의 격리 수준(cGroup limit)을 좁혀가며 스레드 제어로 극복하는 방향 중 실무 클라우드 분산 아키텍처 관점에서는 어떤 방향으로 밸런스를 맞추는 것이 더 이상적인 해법인지 조언을 구합니다.
