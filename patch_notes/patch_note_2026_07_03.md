# WE-MEET 패치노트 (2026.07.03 - 실시간 비용 청구 모델 도입, 스케일인 최적화 및 FedAvg 결과 개선 종합 패치)

본 패치노트는 이기종 가상 클러스터 분산 학습 런타임인 **WE-MEET**의 디스크 공간 누수 방지를 위한 임시 가중치 자동 소거 기능, FedAvg 결합 결과 출력 방식 교정, 실시간 초당 비용 차감 모델 및 유휴(IDLE) 시간 기반 자원 회수(Scale-in) 최적화 패치 내역을 기술합니다.

---

## 🧹 1. 임시 가중치 체크포인트(.pt) 파일 자동 정리 (Clean-up) 및 Graceful Shutdown 고도화
* **체크포인트 파편 자동 제거 (`utils.py`)**:
  * **장애 증상:** 매 에포크마다 저장되던 `data/checkpoint_*.pt` 가중치 파일들이 학습이 성공적으로 종료된 후에도 제거되지 않고 남아 디스크 공간을 기하급수적으로 낭비하던 문제를 해결했습니다.
  * **해결 내용:** 
    * **Map-Merge 성공 시:** 맵 서브태스크들이 생성한 임시 체크포인트 파일(`checkpoint_*_epoch_*.pt`)을 `glob` 모듈로 추적하여 일괄 삭제 조치했습니다.
    * **단일 학습 성공 시:** 학습 중 누적된 임시 에포크 체크포인트 파일들을 성공 즉시 소거하도록 하였습니다.
    * *참고: 학습 중 예기치 않은 노드 회수/단절 시, 중단점 복구(Fault Tolerance)를 위해 실패한 작업의 체크포인트 파일은 삭제하지 않고 안전하게 보존합니다.*
* **Graceful Shutdown 시 공유 볼륨 및 동적 컨테이너 정리 고도화 (`head.py` / `cluster_manager.py`)**:
  * **장애 증상:** Docker Compose 종료(`Ctrl+C` 또는 `docker compose down`) 시, 동적으로 생성된 Spot 워커 컨테이너들을 정리하기 위해 `container.stop(timeout=2)`를 루프 내에서 개별 호출하다 보니 Docker 데몬의 10초 대기 시간(SIGKILL 강제 종료)을 초과하는 지연이 발생했습니다. 이로 인해 마스터 컨테이너가 잔존 자원을 채 다 치우기 전에 먼저 강제 종료되어 좀비 노드가 호스트에 잔존하고, 공유 볼륨에도 임시 파일들이 누수되는 문제가 있었습니다.
  * **해결 내용:** 
    * **컨테이너 즉시 강제 삭제:** `cleanup_zombie_containers()` 내의 `stop()` 단계를 과감히 생략하고, 즉각 `container.remove(force=True)`를 실행하여 수 밀리초 내에 즉시 회수 및 삭제되도록 최적화했습니다.
    * **공유 볼륨 파일 강제 정화:** `handle_shutdown()` 종료 핸들러 내에 공유 볼륨 내부의 모든 잔존 가중치 파일(`data/checkpoint_*.pt` 및 `data/final_*.pt`)을 `glob`으로 스캔하여 즉시 소거하는 정화 파이프라인을 추가했습니다.

## 🔮 2. FedAvg 수학적 가중치 결합 모델의 추론 검증 결과 대시보드 연동
* **분산 병합 최종 결론 산출 방식 개편 (`utils.py`)**:
  * **기존 문제점:** 분산 학습 완료 시점의 최종 결론(Conclusion) 출력이 단순히 개별 분할 맵(Map) 노드들의 임시 텍스트 출력을 이어 붙여서(`|` 조인) 표시되거나 단순 다수결로 표시되어, 실제 FedAvg 가중치 병합 모델의 결과물로서 불분명하고 애매한 결과를 출력했습니다.
  * **해결 내용:** 병합 연산을 전담한 MERGE/REDUCE 워커의 연산 로그(`r_stat.logs`)로부터 수학적 결합 모델의 직접 추론 검증 로그(`[FedAvg Verification]`) 라인을 파싱 및 추출하여 이를 최종 분석 결론으로 설정했습니다. 이로써 텍스트 조각들이 중복 나열되는 대신, **세 개 워커의 학습 성과가 수학적으로 완전히 융합된 고품질의 완성형 추론 문장(또는 이미지 분류 결과)** 하나가 대시보드 화면에 명확하게 노출됩니다.

## 💸 3. 실시간 노드 상시 구동 비용 차감 (Continuous VM Billing) 도입
* **초당 비용 모델 전환 (`scheduler.py` / `run_benchmark.py` / `utils.py`)**:
  * **기존 문제점:** 기존 스케줄러는 태스크가 성공적으로 완료된 시점에만 실행시간 비례 비용(`task_cost`)을 몰아서 차감했습니다. 이 경우, 동적 스케일아웃으로 Spot 노드를 여러 대 추가해 놓고 아무 작업도 주지 않은 채 유휴(IDLE) 상태로 방치해도 가상 예산이 전혀 깎이지 않는 비현실적인 문제가 발생하여 Q-Learning 에이전트가 스케일인(Scale-in)의 필요성을 전혀 학습하지 못했습니다.
  * **해결 내용:**
    * 태스크 완료 시점의 비용 차감 방식(`task_cost` 누적 차감)을 비활성화하고, AWS/GCP 등 실제 퍼블릭 클라우드처럼 **가동 중인 모든 워커 노드의 시간당 가동 비용을 초 단위로 환산하여 매 초마다 가상 예산에서 실시간 차감**하는 상시 구동 비용 모델로 개편했습니다.
    * 이를 통해 클러스터를 넓게 유지하면 예산이 빠르게 소모되므로, 작업 대비 과도한 스케일아웃을 억제하고 적시에 스케일인할 수 있도록 강력한 비용-SLA 성능 트레이드오프 관계를 설계했습니다. 또한 비용이 저렴한 Spot-B 노드의 활용도를 높이는 방향으로 에이전트 의사결정 수렴이 강화되었습니다.

## 📉 4. 노드 유휴 시간(Idle Duration) 감지 기반 탄력적 스케일인(Scale-In) 개편
* **대기열 상태 무관 유휴 자원 정리 (`scheduler.py` / `run_benchmark.py`)**:
  * **기존 문제점:** 기존 스케일인 조건은 `대기 큐에 태스크가 아예 없는(q_len == 0)` 상태에서만 유휴 대기 타이머를 측정했습니다. 이로 인해 태스크가 꾸준히 조금씩 유입되는 실환경에서는 큐가 0이 되지 않아 한 번 증설된 스팟 인스턴스들이 절대로 꺼지지 않고 영구 기동되며 예산을 낭비했습니다.
  * **해결 내용:** 대기 큐 크기와 상관없이, **클러스터 내에 유휴(IDLE) 상태인 스팟 노드가 감지되는 시간**을 기준으로 스케일인 타이머를 작동시켰습니다. 스팟 노드가 놀고 있는 시간이 누적 10초 이상 지속되면 초과 증설된 자원으로 판단하여 즉각 안전하게 회수 처리합니다.

## 🏷️ 5. 'REDUCE' 단계 명칭의 'MERGE' 단계 전환 (Head 스케줄러 & 대시보드)
* **대시보드 및 스케줄러 모듈 이름 교체**:
  * 분산 합산 연산의 성격을 반영하여 Head 노드 스케줄러 상의 태스크 및 모델 타입 명칭을 `REDUCE`에서 `MERGE`로, 태스크 ID 접미사를 `-reduce`에서 `-merge`로 통일 전환했습니다.
  * 대시보드 배지 표기를 `(MERGE)`로 갱신하고 설명 플레이스홀더를 "분산 병합(Map-Merge)"으로 명확히 개선했습니다.
  * 벤치마크 테스트 스크립트(`run_benchmark.py`)에도 동일 명칭 변경을 동기화 적용하여 테스트 신뢰성을 유지했습니다.
